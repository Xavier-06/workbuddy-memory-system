# 自动化：定期记忆提取

**作用**：每天扫描每日日志，把有价值的内容蒸馏到主题记忆文件。自动维护记忆系统，不用人工整理。

## 工作流程

```
每天定时触发
    │
    ▼
扫描 ~/.workbuddy/memory/YYYY-MM-DD.md 每日日志
    │
    ├── 有新内容？
    │     │
    │     ├── YES → 写入/更新对应主题文件
    │     │         └── 更新 MEMORY.md 索引
    │     │             └── 删除已被吸收的日志
    │     │
    │     └── NO → 静默退出（不写空记录）
    │
    └── 日志 > 30 天？
          │
          └── YES → 蒸馏到 MEMORY.md，删除原日志
```

## 在 WorkBuddy 中配置

### 方法一：使用自动化任务（推荐）

1. 打开 WorkBuddy
2. 创建新自动化任务
3. 设置触发条件：
   - 类型：定时触发
   - 时间：每天早上 9:00（或你习惯的时间）
4. 设置任务内容：
   - 调用记忆管理脚本，或
   - 直接让 AI 执行 extractMemories 逻辑

### 方法二：使用 cron（如果你能访问系统 cron）

```bash
# 每天早上 9 点执行记忆提取
0 9 * * * /usr/bin/python3 /path/to/extractMemories.py >> ~/.workbuddy/logs/extract.log 2>&1
```

## extractMemories 的判断标准

| 情况 | 处理方式 |
|------|---------|
| 内容已被主题文件覆盖 | 静默退出 |
| 新知识/决策/偏好/规则 | 创建或更新主题文件 |
| 日志 > 30 天 | 蒸馏精华到 MEMORY.md，删除原日志 |
| 无实质内容 | 静默退出，不刷存在感 |

## 静默退出原则

extractMemories 在以下情况静默退出，不写任何记录：
- 每日日志为空
- 内容已被现有主题文件覆盖
- 没有新知识需要提取

**为什么要静默？** 不产生垃圾日志。如果每次都写"扫描了 X 个日志，0 条新记忆"，久而久之日志本身就变成噪音。

## 验证是否正常运行

检查 ~/.workbuddy/memory/ 下的文件：
- MEMORY.md 索引行数是否在增长
- 主题文件是否在更新
- 是否有孤立的每日日志超过 30 天未清理

## 出问题了怎么办

1. 检查 ~/.workbuddy/logs/extract.log
2. 手动运行一次看报错
3. 检查 MEMORY.md 索引是否与实际文件一致（无悬空指针）
